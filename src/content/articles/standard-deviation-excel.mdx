A standard deviation Excel formula almost always comes down to a choice between two functions — `STDEV.S` for a sample and `STDEV.P` for a complete population — and getting that choice right matters far more than the arithmetic itself, which Excel finishes in under a second. Calculating standard deviation with Excel is fast once you know which function matches your data: `STDEV.S` divides by `n − 1` and is the right default almost every time, while `STDEV.P` divides by `n` and only applies when your range holds every member of the group, with no exceptions. The real risk isn't the formula — it's a range that quietly reaches past your data (a whole-column reference picking up stray values below it), a hidden or filtered row the function still counts, or a number stored as text, each of which changes the result without throwing an error.

## Which Excel Function Should You Use: STDEV.S or STDEV.P?

Use `STDEV.S` whenever your data is a sample drawn from a larger group, and reserve `STDEV.P` for the rare case where your range holds every member of a closed, complete population. The [NIST/SEMATECH e-Handbook of Statistical Methods](https://www.itl.nist.gov/div898/handbook/eda/section3/eda356.htm) defines the standard deviation as "the square root of the variance" and notes that it "restores the units of the spread to the original data units," unlike the <Link to={routes.article('variance')}>variance</Link>, which squares them — a result of 5 minutes means a typical value sits about 5 minutes from the mean, while the variance would report 25 minutes-squared for the same spread. On paper this is the population standard deviation `σ` or sample standard deviation `s`; see the <Link to={routes.article('standard-deviation-symbol')}>standard deviation symbol</Link> guide for how that notation maps onto Excel's two function names.

Per [Microsoft's documentation for STDEV.S](https://support.microsoft.com/en-us/excel/functions/stdev-s-function), the function "assumes that its arguments are a sample of the population" and computes the standard deviation "using the n-1 method." [STDEV.P's documentation](https://support.microsoft.com/en-us/excel/functions/stdev-p-function) states the opposite assumption — that the arguments represent the entire population — and divides by `n` instead. Both functions accept the same argument shapes: a range like `A1:A100`, a list of individual values, or a mix of both, via `=STDEV.S(number1, [number2], ...)` or `=STDEV.P(number1, [number2], ...)`.

The `n − 1` denominator exists because a sample systematically underestimates the spread of the full population it was drawn from; dividing by one less than the count corrects that bias. [OpenStax's *Introductory Statistics*, §2.7](https://openstax.org/books/introductory-statistics/pages/2-7-measures-of-the-spread-of-the-data) walks through this same relationship between the sample standard deviation `s` and the population standard deviation `σ` in more formal terms. Excel is not the only tool built around this distinction: [R's `sd()` function](https://stat.ethz.ch/R-manual/R-devel/library/stats/html/sd.html) always "uses denominator n - 1," matching `STDEV.S`, while [NumPy's `std()` function](https://numpy.org/doc/stable/reference/generated/numpy.std.html) defaults to `ddof=0`, matching `STDEV.P`. For the full derivation of why the correction works, see the dedicated <Link to={routes.article('standard-deviation')}>standard deviation</Link> guide — this page focuses on applying the two functions correctly inside a spreadsheet, not re-deriving the formula.

Microsoft retains `STDEV` and `STDEVP` as legacy names: `STDEV` is mathematically identical to `STDEV.S`, and `STDEVP` is identical to `STDEV.P`. [STDEVP's own documentation](https://support.microsoft.com/en-us/excel/functions/stdevp-function) confirms it "assumes that its arguments are the entire population." Both older names still work in current Excel, including Excel 365, but Microsoft recommends the `.S`/`.P` names in new workbooks because the suffix makes the sample-versus-population choice explicit at a glance.

<Callout variant="tip" title="Pro tip">
When you are not sure whether your data is a sample or a population, default to STDEV.S. Treating a sample as a population (using STDEV.P) understates variability every time; treating a true population as a sample (using STDEV.S) only adds a small, conservative cushion.
</Callout>

## How Do STDEVA and STDEVPA Handle Non-Numeric Cells?

`STDEVA` (sample) and `STDEVPA` (population) exist for the specific case where a range deliberately mixes numbers with `TRUE`/`FALSE` values you want included in the calculation. [Microsoft's documentation for STDEVA](https://support.microsoft.com/en-us/excel/functions/stdeva-function) is unambiguous on two of the three non-numeric cases: a `TRUE` inside a cell reference counts as 1, and a `FALSE` inside that same reference counts as 0 — the remarks state directly that "arguments that contain TRUE evaluate as 1; arguments that contain text or FALSE evaluate as 0." It's just as clear that a genuinely blank cell in that reference is ignored rather than counted as 0. Text is the one case the documentation does not settle: the same remarks section goes on to say that "empty cells and text values in the array or reference are ignored" — which flatly contradicts the "text... evaluate as 0" it states earlier in that same paragraph. Rather than pick a side Microsoft's own page leaves open, treat a text value inside a `STDEVA`/`STDEVPA` reference as unresolved and test it directly against your own data before relying on the result. `STDEV.S` and `STDEV.P`, by contrast, are unambiguous: they exclude blanks, text, and logical values alike from a reference.

Because folding a `FALSE` into the calculation as a zero can pull a result toward zero when you didn't mean to include that cell at all, stick with `STDEV.S`/`STDEV.P` unless your range genuinely needs `TRUE`/`FALSE` counted as numbers. If you need a dispersion measure that's less sensitive to how individual cells are coded in the first place, the <Link to={routes.article('mean-absolute-deviation')}>mean absolute deviation</Link> guide covers an alternative that avoids squaring distances from the mean entirely.

## How Do You Calculate Standard Deviation for a Subset, Multiple Ranges, or Across Sheets in Excel?

`STDEV.S` and `STDEV.P` aren't limited to one contiguous range: pass several ranges as separate arguments, wrap a condition in `FILTER` to restrict the calculation to a subset, or write a 3-D reference to span matching cells across several sheets. Each approach suits a different layout, covered one at a time below.

**Non-contiguous ranges.** Both `STDEV.S` and `STDEV.P` accept more than one range as separate arguments:

```
=STDEV.S(A1:A8, C1:C5)
```

Excel treats the two ranges as one combined data set — useful when your values are split across non-adjacent columns or separate tables.

**Named ranges.** Assigning a name to a range (Formulas → Define Name) lets you write a self-documenting formula:

```
=STDEV.S(DeliveryTimes)
```

A named range defined as an Excel Table or a dynamic named range also resizes automatically as rows are added, so the formula keeps covering the full data set without manual edits.

**Conditional subsets.** Excel has no dedicated `STDEVIF` function, but in Excel 365 and Excel 2021 you can combine `STDEV.S` with [the `FILTER` function](https://support.microsoft.com/en-us/excel/functions/filter-function), which "filters an array based on a Boolean (True/False) array":

```
=STDEV.S(FILTER(B2:B100, A2:A100="East"))
```

This computes the standard deviation of only the rows where column A equals "East." In older Excel versions without `FILTER`, the same result comes from an array formula entered with Ctrl+Shift+Enter:

```
=STDEV.S(IF(A2:A100="East", B2:B100))
```

Excel adds the surrounding braces automatically when you press Ctrl+Shift+Enter — type the formula itself, not the braces.

**Across multiple sheets.** A 3-D reference spans every sheet between two tab names:

```
=STDEV.S(Sheet1:Sheet3!A1:A10)
```

Excel treats the matching cell range on every sheet from `Sheet1` through `Sheet3` as one combined data set, which only works cleanly when every sheet shares the same layout.

## How Do You Add Standard Deviation Error Bars to an Excel Chart?

Select the chart, open Chart Elements, check Error Bars, then pick Standard Deviation — but know what that option actually draws first: it computes a single standard deviation from every plotted point across the whole series and applies that one value to every point uniformly, rather than a separate, per-point standard deviation drawn from each point's own underlying data. [Microsoft's documentation on error bars](https://support.microsoft.com/en-us/office/add-change-or-remove-error-bars-in-a-chart) spells out the equation it uses: the Standard Deviation option is computed from "M = arithmetic mean" and "ny = total number of data values in all series," so every error bar on the chart ends up the same length by construction.

1. Click the chart to select it.
2. Click the **+** (Chart Elements) button that appears to the right of the chart.
3. Check **Error Bars**, then select **More Options**.
4. Under **Error Amount**, pick **Standard Deviation** for the single, chart-wide value described above, and set the multiplier — 1 is the most common choice.

If you actually need a different standard deviation bar on each point — say, one `STDEV.S` per group in a bar chart — the built-in option can't do that. Instead, choose **Custom**, then **Specify Value**, and point the Positive and Negative Error Value boxes at a range of cells holding a separate `STDEV.S` result for each point; Microsoft's documentation confirms "you can also define error values as a range of cells from the same Excel workbook." That route gives every bar its own, genuinely computed standard deviation instead of one shared value borrowed from the whole series.

Either way, error bars let a reader judge at a glance whether the spread is large or small relative to the values being compared, without reading the underlying numbers.

## How Do You Use STDEV.S Inside Other Excel Formulas?

`STDEV.S` and `STDEV.P` nest cleanly inside larger formulas, which is where standard deviation earns its keep in data-quality checks and outlier screening. To count how many values sit more than one standard deviation above the <Link to={routes.article('how-to-find-the-mean')}>mean</Link>:

```
=COUNTIF(A1:A8, ">"&(AVERAGE(A1:A8)+STDEV.S(A1:A8)))
```

On the eight delivery times used in the worked example below, `AVERAGE` returns 21.5 and `STDEV.S` returns about 4.2426, so the threshold is roughly 25.74 minutes. Exactly one value — 30 minutes — exceeds it, so this formula returns **1**.

Excel's [`STANDARDIZE` function](https://support.microsoft.com/en-us/excel/functions/standardize-function) turns the same standard deviation into a <Link to={routes.article('z-score')}>z-score</Link> directly, "a normalized value from a distribution characterized by mean and standard_dev":

```
=STANDARDIZE(30, 21.5, 4.2426)
```

This returns approximately **2.00** — the 30-minute delivery sits about two sample standard deviations above the mean, which is exactly the kind of flag a data-quality check or outlier screen is built to catch.

## A Worked Example: Courier Delivery Times

A regional courier manager wants to know how consistent one driver's delivery times are before promising customers a delivery window. She pulls 8 delivery times, in minutes, from Tuesday's route sheet — out of roughly 40 stops the driver made that day, so this is clearly a **sample**, not the full population of deliveries.

### Step 1: Enter the data

| Cell | Delivery time (min) |
|------|----------------------|
| A1 | 18 |
| A2 | 22 |
| A3 | 19 |
| A4 | 25 |
| A5 | 21 |
| A6 | 30 |
| A7 | 20 |
| A8 | 17 |

### Step 2: Choose the right function

These 8 times are a sample drawn from a larger day of deliveries, so `STDEV.S` applies here — not `STDEV.P`.

### Step 3: Enter the formulas and verify by hand

```
=STDEV.S(A1:A8)   → 4.2426
=STDEV.P(A1:A8)   → 3.9686
```

**Mean:**

```
x̄ = (18 + 22 + 19 + 25 + 21 + 30 + 20 + 17) / 8 = 172 / 8 = 21.5
```

**Squared deviations from the mean:**

| Value | Deviation | Squared deviation |
|-------|-----------|--------------------|
| 18 | −3.5 | 12.25 |
| 22 | 0.5 | 0.25 |
| 19 | −2.5 | 6.25 |
| 25 | 3.5 | 12.25 |
| 21 | −0.5 | 0.25 |
| 30 | 8.5 | 72.25 |
| 20 | −1.5 | 2.25 |
| 17 | −4.5 | 20.25 |
| **Sum** | | **126** |

```
STDEV.S: s = √(126 / (8 − 1)) = √(126 / 7) = √18 ≈ 4.2426
STDEV.P: σ = √(126 / 8) = √15.75 ≈ 3.9686
```

Excel's output matches the hand calculation exactly. The Bessel correction — dividing by `n − 1 = 7` instead of `n = 8` — pushes the sample estimate above the population value, which is the intended effect of correcting for a sample's tendency to underestimate spread.

**Decision.** The manager should report the sample standard deviation — about 4.24 minutes — when estimating how consistent this driver's deliveries are likely to be going forward, since 8 stops out of roughly 40 is a sample, not the whole day. Paste these same eight values into the calculator above to confirm both results without redoing the arithmetic by hand.

<Callout variant="tip" title="Pro tip">
Whenever you share a standard deviation figure, name the function that produced it — "STDEV.S, n = 8" rather than a bare number. The gap between STDEV.S and STDEV.P shrinks as n grows, but on a small sample like this one it's large enough that leaving the method unstated makes the figure impossible to check.
</Callout>

## What Causes a Wrong Standard Deviation Result in Excel?

Knowing what can go wrong saves hours of troubleshooting when a number looks off.

- **Using STDEV.P on sample data.** This is the costliest mistake, because `STDEV.P` always returns a value at or below `STDEV.S` on the same numbers. Treating a sample as if it were the whole population understates variability, and any confidence interval or control limit built on that understated number inherits the error.
- **A whole-column reference picking up values you didn't mean to include.** A text header like "Minutes" in A1 isn't actually the risk — `STDEV.S` and `STDEV.P` ignore text in a reference and calculate over exactly the numeric rows you intended. The real risk is a reference like `=STDEV.S(A:A)`: it keeps reading all the way down the column, so a note typed below the data, a running total, or the start of a second table further down the sheet gets silently folded into the result. An Excel Table (Ctrl+T) resizes its own references automatically, which avoids this without you having to track the last row by hand.
- **Confusing a blank cell with a zero.** `STDEV.S` and `STDEV.P` exclude a genuinely blank cell from both the count and the result; a cell containing `0` is included and pulls the result toward zero. If a missing measurement means "no data," leave it empty — entering `0` changes the answer.
- **Numbers stored as text.** Values imported from another system sometimes arrive as text that merely looks numeric. `STDEV.S` and `STDEV.P` ignore them, quietly shrinking the effective sample size. The small green triangle in a cell's top-left corner is Excel's warning sign; Data → Text to Columns, or multiplying the column by 1, converts the values to true numbers.
- **Hidden or filtered rows that still get counted.** Filtering a table down to one region's orders doesn't stop `STDEV.S` or `STDEV.P` from reading every row in the range, including the ones currently hidden by the filter. The same applies to a row hidden manually with Hide Rows. `SUBTOTAL(7, ...)` matches `STDEV.S` and `SUBTOTAL(8, ...)` matches `STDEV.P`; add 100 (`SUBTOTAL(107, ...)` or `SUBTOTAL(108, ...)`) to also exclude manually hidden rows. [AGGREGATE's documentation](https://support.microsoft.com/en-us/excel/functions/aggregate-function) uses the same two function numbers — 7 for `STDEV.S`, 8 for `STDEV.P` — but the function number by itself does not skip hidden rows. AGGREGATE's `options` argument has to be set to 1, 3, 5, or 7 to ignore hidden rows, for example `=AGGREGATE(7, 5, A1:A100)`. Leave `options` at 0 or omit it, as in `=AGGREGATE(7, 0, A1:A100)`, and the function only ignores nested `SUBTOTAL`/`AGGREGATE` calls — every hidden row in the range still gets counted.
- **Treating a tiny sample's result as precise.** With fewer than five or six values, a single extreme observation can shift the standard deviation substantially. Report the sample size `n` alongside the standard deviation so a reader can judge how stable the estimate is — a standard deviation of 3.5 from `n = 4` carries far less weight than the same value from `n = 200`.

<Callout variant="quote" source="SUBTOTAL function, Microsoft Support" sourceHref="https://support.microsoft.com/en-us/excel/functions/subtotal-function">
1-11 includes manually-hidden rows, while 101-111 excludes them; filtered-out cells are always excluded.
</Callout>

## Statohub's Take on Standard Deviation in Excel

Statohub's position is that the function choice, not the arithmetic, is where this calculation actually goes wrong in practice. Spend the extra few seconds confirming sample versus population and scanning the range for a stray value past the data, a blank-versus-zero mixup, or a hidden row before trusting the number — Excel will compute a confident-looking result from flawed inputs without ever flagging the problem. When a quick, disposable first pass is all you need, the <Link to={routes.article('how-to-find-the-range')}>range</Link> is faster to check by eye; reach for the standard deviation once that first look says the data is worth a more careful read.
