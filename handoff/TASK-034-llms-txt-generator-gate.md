## Brief  *(Claude writes -- what Codex needs to execute)*

**Goal:** Make `llms.txt` a generated build artifact instead of a hand-kept
file, so it can never again drift from the published site, and add a build
gate that fails when it does.

**Why this exists:** `public/llms.txt` was hand-maintained and rotted badly.
On 2026-08-16 it listed 20 of 77 published articles and 6 of 10 category
hubs, and omitted the entire Applied Statistics track (the `/applied/`
landing page plus all four Applied hubs and their articles). It was
regenerated by hand in commit `d3ac10a`, but the same rot restarts with the
next article published. Every article the daily cloud routine ships makes
the committed file staler.

**Context / inputs:**
- `scripts/gen-route-ids.mjs` -- the precedent to follow. Node built-ins
  only, no new dependency, reads `src/content/**` directly, runs before
  `astro build` via `package.json`. Match its header-comment style (why the
  script exists, not just what it does) and its one-line stdout summary.
- `scripts/check-links.mjs` -- the precedent for a post-build gate that walks
  `dist/`, collects violations, prints them, and exits non-zero.
- `package.json` `build` script -- current chain is
  `gen-route-ids -> astro build -> check-links -> check-meta-description`.
- `public/llms.txt` -- the current hand-written file. Its shape (heading
  hierarchy, `- [Title](url): description` line format, section order) is the
  spec for the generator's output. Reproduce that shape; do not redesign it.
- `src/content/categories/*.yaml` -- carries `title`, `description`,
  `section` (`learn` | `applied`), and `order`, which drive the grouping and
  the order sections appear in.
- `docs/decisions/0002-flat-url-structure.md` -- trailing-slash rule that the
  emitted URLs must obey.

**Approach (decided -- build to this, do not substitute another):**

Generate **after** `astro build`, from `dist/`, not from the content
collections. Rationale: `dist/sitemap-0.xml` is by definition the exact set
of published, indexable URLs -- draft filtering and noindex exclusion have
already been applied by Astro. Deriving the URL list from `src/content/**`
would mean re-implementing that filtering in a second place, which is the
same class of bug this task exists to kill.

Per-URL title and description come from the built HTML of that page (its
`<title>` and `<meta name="description">`), not from frontmatter, so the file
always states what the page actually says.

Grouping comes from two sources:
- Section and category ordering: parse `src/content/categories/*.yaml`.
  These are flat scalar keys; a minimal reader is fine, but it must throw on
  a file it cannot parse rather than skip it silently.
- Which category a given article belongs to: read the `BreadcrumbList`
  JSON-LD already embedded in each built article page. Applied articles carry
  `Home / Applied Statistics / <Category> / <Article>`; Learn articles carry
  `Home / <Category> / <Article>`.

Write the result to **both** `dist/llms.txt` (what deploys) and
`public/llms.txt` (the committed copy, so the repo stays reviewable and
diffable). Both must be byte-identical at the end of a build.

**Deliverables:**
- [ ] `scripts/gen-llms-txt.mjs` -- generator per the approach above. Node
      built-ins only. No new dependency.
- [ ] `scripts/check-llms-txt.mjs` -- post-build gate. Fails the build when
      any of these hold:
      - a URL in `dist/llms.txt` is not in `dist/sitemap-0.xml`
      - a URL in `dist/sitemap-0.xml` is absent from `dist/llms.txt`
      - `dist/llms.txt` and `public/llms.txt` differ
      Print one line per violation in `check-links.mjs` style, then exit 1.
      The sitemap-index reference in the Optional section is the one
      allowed non-page URL; whitelist it explicitly.
- [ ] `package.json` build chain updated so generation runs after
      `astro build` and the gate runs after generation.
- [ ] `docs/REPO-MAP.md` -- refresh via `node scripts/gen-repo-map.mjs` (do
      not hand-edit the tree), then add the one-line annotation for each new
      script in the `scripts/` block, matching the style of the existing
      `gen-route-ids.mjs` and `check-links.mjs` lines.

**Constraints:**
- Stay in this repo; don't touch sibling folders.
- Node built-ins only. No YAML or Markdown parsing dependency. Wrangler v3
  lock and the rest of ADR 0005 are unchanged by this task.
- Do not touch `src/calc/**`, any layout, or any content file.
- Every emitted internal URL ends in a trailing slash (ADR 0002). The sitemap
  reference is the sole exception, since it is a file not a page.
- The generator must be deterministic: same content in, byte-identical file
  out. No timestamps, no build ids, no "generated on" date in the output --
  those would produce a spurious diff on every build.
- Do not reformat or restructure the existing `public/llms.txt` beyond what
  the generator naturally produces. If your output differs from the current
  committed file in any way other than ordering that you can justify, stop
  and report it in the Work Log rather than committing the difference.

**Definition of done / how to verify:**
- `npm run build` succeeds end to end and prints the generator's summary line
  and the gate's OK line.
- `git status` is clean immediately after a build. This is the key check: it
  proves the generator reproduced the committed file exactly.
- Running `npm run build` twice in a row produces no diff on the second run
  (determinism).
- Negative test, and report the result in the Work Log: temporarily flip one
  published article to `draft: true`, run `npm run build`, and confirm the
  gate fails with a clear message naming that URL. Then revert.
- `npx astro check` reports 0 errors and `npm test` passes (neither should be
  affected, but confirm).
